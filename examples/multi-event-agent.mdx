This example demonstrates how to handle multiple event types within a single agent to create sophisticated annotation workflows.

## Overview

A multi-event agent can:
- React to multiple stages in the annotation lifecycle
- Coordinate actions across different event types
- Implement complex workflow logic
- Share state between event handlers

## Supported Events

| Event | Context Type | Description |
|-------|--------------|-------------|
| `result.submitted` | `ResultContext` | An annotator submitted a result |
| `result.accepted` | `ResultContext` | A result was accepted by QC |
| `result.rejected` | `ResultContext` | A result was rejected by QC |
| `task.completed` | `TaskContext` | A task reached a terminal state |

## Complete Example

```python
from avala_agents import TaskAgent, ResultContext, TaskContext

agent = TaskAgent(
    api_key="avk_...",
    name="workflow-orchestrator",
    project="proj_uid",
)

@agent.on("result.submitted")
def on_result_submitted(context: ResultContext):
    """First-pass quality check on submission."""
    annotations = context.result_data
    confidence = context.result_metadata.get("confidence", 1.0)
    
    if len(annotations) == 0:
        context.reject("No annotations found")
    elif confidence < 0.5:
        context.flag("Low confidence — needs review")
    else:
        context.approve()

@agent.on("result.accepted")
def on_result_accepted(context: ResultContext):
    """Log accepted results for analytics."""
    print(f"Result {context.result_uid} accepted for task {context.task_uid}")
    context.skip()  # acknowledge without further action

@agent.on("task.completed")
def on_task_completed(context: TaskContext):
    """Finalize tasks and trigger downstream processes."""
    print(f"Task {context.task_uid} completed with status: {context.task_status}")
    context.approve()

agent.run()
```

## How It Works

<Steps>
  <Step title="Register multiple handlers">
    Use the `@agent.on()` decorator multiple times to register handlers for different events.

    ```python
    @agent.on("result.submitted")
    def handle_submission(context):
        # Validate submissions
        pass

    @agent.on("result.accepted")
    def handle_acceptance(context):
        # Process accepted results
        pass

    @agent.on("task.completed")
    def handle_completion(context):
        # Finalize completed tasks
        pass
    ```
  </Step>

  <Step title="Use appropriate context types">
    Different events provide different context objects:
    - `ResultContext` for result events (submitted, accepted, rejected)
    - `TaskContext` for task events (completed)

    <Tip>
      Add type hints to get better IDE autocomplete:
      ```python
      from avala_agents import ResultContext, TaskContext

      def on_result_submitted(context: ResultContext):
          # IDE knows context.result_data exists
          pass
      ```
    </Tip>
  </Step>

  <Step title="Share state between handlers">
    Use class-based agents or external storage to share state between event handlers.

    ```python
    class WorkflowAgent:
        def __init__(self):
            self.processed_count = 0
            self.agent = TaskAgent(api_key="avk_...", name="stateful-agent")
            
            self.agent.on("result.submitted")(self.on_submit)
            self.agent.on("task.completed")(self.on_complete)
        
        def on_submit(self, context):
            self.processed_count += 1
            context.approve()
        
        def on_complete(self, context):
            print(f"Total processed: {self.processed_count}")
            context.approve()
        
        def run(self):
            self.agent.run()
    
    WorkflowAgent().run()
    ```
  </Step>
</Steps>

## Advanced: Result Lifecycle Tracking

Track results through their entire lifecycle:

```python
import logging
from datetime import datetime
from avala_agents import TaskAgent, ResultContext

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

agent = TaskAgent(
    api_key="avk_...",
    name="lifecycle-tracker",
)

@agent.on("result.submitted")
def on_submitted(context: ResultContext):
    """Track submission timestamp and validate."""
    logger.info(
        f"[SUBMITTED] Result {context.result_uid} | "
        f"Task: {context.task_name} | "
        f"Annotations: {len(context.result_data)}"
    )
    
    if len(context.result_data) == 0:
        context.reject("Empty submission")
    elif context.result_metadata.get("confidence", 1.0) < 0.5:
        context.flag("Low confidence")
    else:
        context.approve()

@agent.on("result.accepted")
def on_accepted(context: ResultContext):
    """Log successful acceptance."""
    logger.info(
        f"[ACCEPTED] Result {context.result_uid} | "
        f"Project: {context.project_uid}"
    )
    context.skip()

@agent.on("result.rejected")
def on_rejected(context: ResultContext):
    """Track rejections for quality metrics."""
    logger.warning(
        f"[REJECTED] Result {context.result_uid} | "
        f"Task: {context.task_name}"
    )
    context.skip()

agent.run()
```

## Filtering Events by Project or Task Type

Scope your agent to specific projects or task types:

```python
from avala_agents import TaskAgent

# Option 1: Filter by project
agent = TaskAgent(
    api_key="avk_...",
    name="project-specific-agent",
    project="proj_abc123",  # only process this project
)

# Option 2: Filter by task types
agent = TaskAgent(
    api_key="avk_...",
    name="task-type-agent",
    task_types=["image-classification", "object-detection"],
)

# Option 3: Combine both filters
agent = TaskAgent(
    api_key="avk_...",
    name="filtered-agent",
    project="proj_abc123",
    task_types=["image-classification"],
)

@agent.on("result.submitted")
def handle_filtered_results(context):
    # Only receives events matching the filters
    context.approve()

agent.run()
```

<Note>
  Filtering at the agent level is more efficient than filtering in your handler code, as it reduces the number of executions your agent needs to process.
</Note>

## Error Handling Across Events

Implement consistent error handling across all event types:

```python
import logging
from avala_agents import TaskAgent, AgentActionError

logger = logging.getLogger(__name__)

agent = TaskAgent(
    api_key="avk_...",
    name="error-handling-agent",
)

def safe_handler(func):
    """Decorator to add error handling to event handlers."""
    def wrapper(context):
        try:
            func(context)
        except AgentActionError as e:
            logger.error(f"Action failed: {e}")
            raise
        except Exception as e:
            logger.exception(f"Unexpected error in {func.__name__}")
            context.flag(f"Agent error: {str(e)}")
    return wrapper

@agent.on("result.submitted")
@safe_handler
def on_submit(context):
    # Your logic here - errors are handled by decorator
    confidence = context.result_metadata["confidence"]  # might raise KeyError
    if confidence < 0.5:
        context.reject("Low confidence")
    else:
        context.approve()

@agent.on("task.completed")
@safe_handler
def on_complete(context):
    # More logic with automatic error handling
    context.approve()

agent.run()
```

## Context Properties by Event Type

### ResultContext (result.submitted, result.accepted, result.rejected)

| Property | Type | Description |
|----------|------|-------------|
| `result_uid` | `str` | Unique identifier for the result |
| `result_data` | `list[dict]` | Annotation data |
| `result_metadata` | `dict` | Custom metadata |
| `task_uid` | `str` | Parent task identifier |
| `task_name` | `str \| None` | Task name |
| `task_type` | `str \| None` | Task type |
| `project_uid` | `str \| None` | Project identifier |
| `event_type` | `str` | Event that triggered execution |

### TaskContext (task.completed)

| Property | Type | Description |
|----------|------|-------------|
| `task_uid` | `str` | Unique identifier for the task |
| `task_name` | `str \| None` | Task name |
| `task_type` | `str \| None` | Task type |
| `task_status` | `str \| None` | Terminal status (e.g., "completed") |
| `project_uid` | `str \| None` | Project identifier |
| `event_type` | `str` | Event that triggered execution |
